How it works

      

        

          
Encryption

          

            
Your browser generates a key and encrypts the note with AES-GCM before the request is sent. We receive ciphertext and a random ID. Support can't read your note, a subpoena can't produce it, and a database dump is worthless without the key.

          

        

        

          
The key

          

            
The key is placed after the # in the link. Browsers treat that fragment as local — it's never included in the HTTP request, so it never touches our logs, proxies or backups.

          

        

        

          
Bot defense

          

            
Chat apps fetch every link to build a preview, which would open a one-time note before a person ever clicked it. Protected links serve a plain gate to automated fetchers and only decrypt on a real click.

          

        

        

          
Files

          

            
Same path as text, up to 5 MB. Hand off a .env, a service-account JSON or a private key without pasting it into a thread that's searchable for the next four years.

          

        

        

          
Deletion

          

            
On first read the row is deleted, not flagged. If you set an expiry instead, the sweeper removes it whether or not anyone opened it.
