How the production design will work

      

        

          
Encryption

          

            
The planned production service will generate a key in the browser and encrypt with AES-GCM before sending ciphertext. This development build demonstrates the interface only; its encryption and storage backend have not been implemented.

          

        

        

          
The key

          

            
The planned link will place the key after #. Browsers do not include URL fragments in HTTP requests, allowing a future service to keep the key separate from the stored ciphertext.

          

        

        

          
Bot defense

          

            
The planned service will use a human-confirmation gate because chat applications often fetch links to generate previews. Bot detection and consumption controls are not active in this prototype.

          

        

        

          
Files

          

            
The interface accepts a local file selection for demonstration. It does not read, encrypt, upload, or deliver that file in the current build.

          

        

        

          
Deletion

          

            
Production deletion semantics will require backend implementation and independent testing. The current recipient preview resets locally and does not represent a stored database row.
