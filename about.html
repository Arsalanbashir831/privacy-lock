About the project

A smaller footprint for shared secrets.

SecretShare is an early-stage prototype exploring one-time delivery without turning a temporary handoff into a permanent chat record.

The problem

Teams regularly paste API keys, recovery codes, database credentials, and configuration files into channels built for permanent conversation. Those messages become searchable, replicated, backed up, and available to more people than the original exchange required.

The direction

The intended design encrypts content in the sender’s browser, stores only ciphertext, keeps the decryption key in a URL fragment, and removes stored material after its first authorized read or an expiry deadline. That architecture is a goal—not a description of the current implementation.

Current state: the public interface is a development prototype. It does not provide working delivery, encryption, accounts, or a production API.

Publishing principles

The learning center is written to stand on its own. Its guidance does not require SecretShare and distinguishes general security practice from product plans. When claims depend on implementation, the status and security pages identify what has and has not been built.
